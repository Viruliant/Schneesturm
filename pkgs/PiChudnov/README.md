# PiChudnov

Digits of π in any base from 2 to 36, computed with the Chudnovsky series
and exposed to C as a shared/static library plus a header.

Derived from [PIbench](https://github.com/Viruliant/PIbench); used by PIthon
to get digits of π for the snake segments.

## Building

From the monorepo root:

```bash
nix build .#PiChudnov
```

The result contains:
- `./result/include/PiChudnov.h` - generated by `cbindgen` from `src/lib.rs`
- `./result/lib/libpichudnov.so` - shared library
- `./result/lib/libpichudnov.a` - static library

## C API

```c
#include <PiChudnov.h>

unsigned int pichudnov_bits_per_digit(unsigned int base);
size_t       pichudnov_words_needed(unsigned int base, size_t digits);
int          pichudnov_bs(unsigned int base, size_t digits, uint64_t *out, size_t out_words);
int          pichudnov_factorial(unsigned int base, size_t digits, uint64_t *out, size_t out_words);
```

- `pichudnov_bs` uses binary splitting (fast); `pichudnov_factorial` uses
  the plain factorial series (slow, kept as a reference). Both give
  identical output.
- The caller allocates `out`; it must have at least
  `pichudnov_words_needed(base, digits)` words.
- `digits` counts the integer part too: base 10, `digits = 5` → `3 1 4 1 5`.
  In bases 2 and 3 the integer part is two digits (`11`, `10`).
- Return values:

| code | name                     | meaning                          |
|------|--------------------------|----------------------------------|
| 0    | `PICHUDNOV_OK`           | success                          |
| -1   | `PICHUDNOV_ERR_NULL`     | `out` is NULL                    |
| -2   | `PICHUDNOV_ERR_BASE`     | base outside 2..36               |
| -3   | `PICHUDNOV_ERR_BUFFER`   | `out_words` too small            |
| -4   | `PICHUDNOV_ERR_DIGITS`   | `digits` is 0                    |
| -5   | `PICHUDNOV_ERR_INTERNAL` | internal error (should not happen) |

`pichudnov_bits_per_digit` and `pichudnov_words_needed` return 0 for an
invalid base.

## Digit encoding

- Each digit uses `ceil(log2(base))` bits (4 for base 10 and 16).
- Each `uint64_t` holds `64 / bits` digits; digits never span two words and
  unused low bits are 0.
- Most-significant digit first within each word, so for base 10 and 16 a
  word printed with `%016llx` shows the digits directly:
  base 10 → `3141592653589793`, base 16 → `3243f6a8885a308d`.

Decoding digit `i`:

```c
unsigned b = pichudnov_bits_per_digit(base), dpw = 64 / b;
unsigned d = (out[i / dpw] >> (64 - b * (i % dpw + 1))) & ((1u << b) - 1);
```

## Example

```c
#include <stdio.h>
#include <stdlib.h>
#include <PiChudnov.h>

int main(void) {
    size_t digits = 50, words = pichudnov_words_needed(10, digits);
    uint64_t *out = calloc(words, sizeof *out);
    if (pichudnov_bs(10, digits, out, words) != PICHUDNOV_OK) return 1;

    unsigned b = pichudnov_bits_per_digit(10), dpw = 64 / b;
    for (size_t i = 0; i < digits; i++)
        putchar('0' + ((out[i / dpw] >> (64 - b * (i % dpw + 1))) & ((1u << b) - 1)));
    putchar('\n');
    free(out);
}
```

```bash
cc example.c -I./result/include -L./result/lib -lpichudnov -Wl,-rpath,./result/lib
```

Linking the static `libpichudnov.a` instead also needs `-lpthread -ldl -lm`.

## Development

```bash
cargo test --release   # algorithms agree, known first words, error codes
```

After changing dependencies, regenerate the lock file; `package.nix` reads
hashes straight from `Cargo.lock`, so there is no `cargoHash` to update:

```bash
nix-shell -p cargo --run "cargo generate-lockfile"
```
