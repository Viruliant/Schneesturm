## Git Workflow for nix build Testing

Both minimus and PIthon are git submodules. `nix build` fetches source
from the git repo (committed content), NOT the working tree.
Uncommitted edits are invisible to `nix build`.

### To test changes with nix build:

```bash
# 1. Make edits to source files
# 2. Commit in the submodule
cd pkgs/minimus && git add -A && git commit -m "test: description"
cd pkgs/PIthon && git add -A && git commit -m "test: description"

# 3. Update parent repo's submodule reference
cd /path/to/root
git add pkgs/minimus pkgs/PIthon
git commit -m "update submodules"

# 4. Update flake lock to pick up new submodule commits
nix flake lock --update-input minimus
nix flake lock --update-input PIthon
# or both at once:
nix flake lock --update-input minimus --update-input PIthon

# 5. Build
nix build .#PIthon
```

### Quick test branch workflow:

```bash
# Create a temp branch, commit everything, build, then discard
git checkout -b temp-test
cd pkgs/minimus && git add -A && git commit -m "test"
cd pkgs/PIthon && git add -A && git commit -m "test"
cd /path/to/root
git add pkgs/minimus pkgs/PIthon && git commit -m "test"
nix flake lock --update-input minimus --update-input PIthon
nix build .#PIthon

# After test, go back:
git checkout main
git branch -D temp-test
```

### Discarding temp commits:

```bash
# In submodule - soft reset to keep files but undo commits
cd pkgs/minimus && git reset --soft HEAD~1
cd pkgs/PIthon && git reset --soft HEAD~1

# In parent - undo submodule pointer update
git reset --soft HEAD~1
```

## `#if INTERFACE` Pattern (makeheaders)

makeheaders generates `.h` files from `.c` files. The `INTERFACE`
macro controls what goes into the generated header vs stays local.

### How it works:

- When **makeheaders runs**: `INTERFACE` is implicitly 1
  - Code inside `#if INTERFACE` → extracted to the `.h` file
  - Code inside `#if !INTERFACE` → skipped (stays in `.c` only)

- When **gcc compiles** the `.c` file: `INTERFACE` is 0 (undefined)
  - Code inside `#if INTERFACE` → skipped (already in `.h`)
  - Code inside `#if !INTERFACE` → compiled locally (types, macros, static funcs)

### The generated `.h` file:

- Starts with `#undef INTERFACE` (resets to 0)
- Contains: function prototypes, exported types, exported macros
- Does NOT contain: function bodies, local types, static functions

### In FileIO.c:

```c
#if !INTERFACE
// LOCAL: types and macros only needed by this .c file
DEFINE_LLDECK(uint8_t)   // generates linked list types/functions locally
typedef struct { ... } date;
#endif

#include "FileIO.h"      // generated by makeheaders — prototypes only

// Public functions — makeheaders auto-generates prototypes in .h
date get_system_date() { ... }
void print_date(date dt) { ... }

#if INTERFACE
// EXPORTED: types/macros that consumers need
typedef struct { ... } byte4vars;
#endif
```

### Rule of thumb:

- `#if !INTERFACE` → local implementation (types, macros, static funcs)
- `#if INTERFACE` → public API (types/macros other files need)
- Function definitions outside any guard → auto-exported by makeheaders
